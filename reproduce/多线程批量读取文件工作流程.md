# 代码工作流程示例

## 场景设置
- **文件总数**: 10 个文件 (file1.txt ~ file10.txt)
- **BATCH_SIZE**: 2 (每批处理 2 个文件)
- **max_workers**: 4 (最多 4 个线程并行读取)

## 详细执行流程

### 阶段 1: 初始化线程池和提交任务
```python
# 创建线程池，最多 4 个工作线程
executor = ThreadPoolExecutor(max_workers=4)

# 提交所有 10 个文件的读取任务到线程池
futures = [
    executor.submit(load_txt_file, "file1.txt"),  # 任务 1
    executor.submit(load_txt_file, "file2.txt"),  # 任务 2
    executor.submit(load_txt_file, "file3.txt"),  # 任务 3
    executor.submit(load_txt_file, "file4.txt"),  # 任务 4
    executor.submit(load_txt_file, "file5.txt"),  # 任务 5
    executor.submit(load_txt_file, "file6.txt"),  # 任务 6
    executor.submit(load_txt_file, "file7.txt"),  # 任务 7
    executor.submit(load_txt_file, "file8.txt"),  # 任务 8
    executor.submit(load_txt_file, "file9.txt"),  # 任务 9
    executor.submit(load_txt_file, "file10.txt"), # 任务 10
]
```

**说明**: 
- 所有任务立即提交到线程池
- 线程池最多同时执行 4 个任务（因为 max_workers=4）
- 其他任务在队列中等待

---

### 阶段 2: 并行读取和处理（时间线示例）

#### 时刻 T1: 前 4 个任务开始执行
```
线程 1: 读取 file1.txt ──────────┐
线程 2: 读取 file2.txt ──────────┤ 并行执行
线程 3: 读取 file3.txt ──────────┤
线程 4: 读取 file4.txt ──────────┘
```

#### 时刻 T2: file2.txt 和 file4.txt 先完成
```
buffer = []  # 初始为空

# file2.txt 完成
buffer.append("file2.txt 的内容")  # buffer = ["file2.txt 的内容"]
# buffer 长度 = 1 < BATCH_SIZE(2)，继续等待

# file4.txt 完成
buffer.append("file4.txt 的内容")  # buffer = ["file2.txt 的内容", "file4.txt 的内容"]
# buffer 长度 = 2 >= BATCH_SIZE(2)，触发插入！

# 执行插入
rag.insert(["file2.txt 的内容", "file4.txt 的内容"])
buffer.clear()  # buffer = []
```

**说明**: 
- 文件完成的顺序是随机的（取决于 I/O 速度）
- 一旦 buffer 达到 BATCH_SIZE，立即插入并清空 buffer

#### 时刻 T3: file1.txt 和 file3.txt 完成，file5.txt 开始
```
# file1.txt 完成
buffer.append("file1.txt 的内容")  # buffer = ["file1.txt 的内容"]

# file3.txt 完成
buffer.append("file3.txt 的内容")  # buffer = ["file1.txt 的内容", "file3.txt 的内容"]
# buffer 长度 = 2 >= BATCH_SIZE(2)，触发插入！

rag.insert(["file1.txt 的内容", "file3.txt 的内容"])
buffer.clear()  # buffer = []

# 线程池继续处理剩余任务
线程 1: 读取 file5.txt ──────────┐
线程 2: 读取 file6.txt ──────────┤ 新的任务开始
线程 3: 读取 file7.txt ──────────┤
线程 4: 读取 file8.txt ──────────┘
```

#### 时刻 T4: 继续处理剩余文件
```
# file6.txt 和 file8.txt 完成
buffer.append("file6.txt 的内容")
buffer.append("file8.txt 的内容")
rag.insert(["file6.txt 的内容", "file8.txt 的内容"])
buffer.clear()

# file5.txt 和 file7.txt 完成
buffer.append("file5.txt 的内容")
buffer.append("file7.txt 的内容")
rag.insert(["file5.txt 的内容", "file7.txt 的内容"])
buffer.clear()

# file9.txt 和 file10.txt 完成
buffer.append("file9.txt 的内容")
buffer.append("file10.txt 的内容")
rag.insert(["file9.txt 的内容", "file10.txt 的内容"])
buffer.clear()
```

---

### 阶段 3: 处理剩余文件（如果文件数是奇数）

假设有 11 个文件，最后会剩下 1 个：

```
# 前 10 个文件已处理（5 批，每批 2 个）
# buffer = ["file11.txt 的内容"]  # 只有 1 个，不足一批

# 循环结束后，检查 buffer
if buffer:  # buffer 不为空
    rag.insert(["file11.txt 的内容"])  # 插入剩余的文件
```

---

## 关键特点

### 1. **并行读取**
- 多个文件同时读取，提高 I/O 效率
- 不等待所有文件读完才开始处理

### 2. **流式处理**
- 边读边处理，内存占用小
- 不需要一次性加载所有文件到内存

### 3. **批量插入**
- 每 BATCH_SIZE 个文件合并插入
- 减少 `rag.insert()` 调用次数，提高效率

### 4. **保持文档边界**
- 使用列表 `rag.insert(buffer)` 而不是拼接字符串
- 每个文件保持独立的文档 ID，避免实体/关系混淆

## 时间线总结

```
时间轴: ──────────────────────────────────────────────────→

T1: [file1, file2, file3, file4] 开始读取
    ↓
T2: [file2, file4] 完成 → 插入批次1 → buffer清空
    ↓
T3: [file1, file3] 完成 → 插入批次2 → buffer清空
    ↓
T4: [file5, file6, file7, file8] 开始读取
    ↓
T5: [file6, file8] 完成 → 插入批次3 → buffer清空
    ↓
T6: [file5, file7] 完成 → 插入批次4 → buffer清空
    ↓
T7: [file9, file10] 完成 → 插入批次5 → buffer清空
    ↓
完成！
```

---

## 优势

1. **高效**: 并行读取 + 批量插入，充分利用系统资源
2. **内存友好**: 不一次性加载所有文件
3. **灵活**: 可以调整 `max_workers` 和 `BATCH_SIZE` 平衡速度和资源
4. **可靠**: 即使文件数不是 BATCH_SIZE 的倍数，也能正确处理剩余文件
